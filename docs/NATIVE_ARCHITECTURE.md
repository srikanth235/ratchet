# Native architecture (v0): Rust server + native Mac app

Status: agreed direction, not started. Replaces the Electron + TypeScript stack in one cut (v0 has no
users, so no incremental migration). The TypeScript packages stay in the repo as the **executable spec**
until the Rust and Swift versions reach parity, then they are deleted.

Why: code generation is no longer the bottleneck with coding agents, so we optimize for performance and
UX, not for one language everywhere.

## Decisions

| Topic | Decision |
|---|---|
| Server | Rust `ratchetd`, a long-lived local daemon |
| Desktop | Native macOS app, SwiftUI (AppKit where SwiftUI falls short), built with the BAMA skills in `.claude/skills/` |
| Platforms | macOS 26+ only in v0. No Linux or Windows desktop app for now; `ratchetd`, the CLI and `ratchet-bench` still build for Linux because CI and the bench hosts need them |
| Deployment | **Local only in v0.** A cloud `ratchetd` is a later step over the same API |
| Contract | OpenAPI generated from Rust (`utoipa`), Swift client generated by `swift-openapi-generator`; server-sent events for live updates |
| Ledger | SQLite via `sqlx` (append-only tables as today, one migration pre-release) |
| Secrets | macOS Keychain, owned by `ratchetd` (the app never holds AWS or API keys) |
| Ports pattern | Kept: every external system has a real and a mock implementation; simulation mode stays for demos and tests |
| Electron, React, Tauri | Dropped |

## Processes

```text
Ratchet.app (SwiftUI)  ──unix socket: HTTP + SSE──►  ratchetd (Rust, LaunchAgent)
ratchet CLI (Rust)     ──same socket──────────────►     │
                                                       ├─ ledger (SQLite, ~/Library/Application Support/Ratchet)
                                                       ├─ local agents: claude / codex CLIs in git worktrees
                                                       ├─ GitHub (octocrab), AWS (aws-sdk-rust), tofu (subprocess)
                                                       └─ cloud sandbox: evaluator hosts run `ratchet-bench` (Rust)
```

- `ratchetd` is registered as a LaunchAgent (`SMAppService.agent(plistName:)`) on first launch, so runs survive
  quitting the app. It is the single writer of the ledger. The app bundle carries it: `Contents/Helpers/ratchetd`
  and `ratchet` (universal binaries from `build.sh`) and the plists in `Contents/Library/LaunchAgents/`
  (`com.ratchet.ratchetd.plist` runs `serve --mode real`, `...demo.plist` runs `serve --mode sim --ledger :memory:`
  for trying the app without accounts; the plists are printed by `ratchetd launchagent print --bundle-program`).
  Until the socket answers the app shows "Starting Ratchet…"; if macOS wants approval it shows a prompt that opens
  System Settings, Login Items. Settings can restart or stop the agent and switch demo mode. The `ratchet` CLI is
  symlinked into `/usr/local/bin` only on the user's click.
- The app keeps no state of its own beyond view preferences. It renders the last snapshot instantly on
  launch, then applies the SSE stream; nothing polls.
- Socket auth: the socket file is `0600` in the user's Application Support folder plus a per-boot
  token file next to it, read by the app on every request. No TCP port in v0.
- Secrets: the app never holds them. Connector sign-in sends a key to the daemon once (GitHub uses the device
  flow, where the daemon polls GitHub itself); the daemon stores it with `KeychainSecretStore` (generic passwords,
  service `ratchet`). The daemon is the only reader, so no keychain access group is needed.
- The CLI is a thin client of the same API (`ratchet run`, `ratchet status`, `ratchet init --template`),
  so agents and scripts drive exactly what the app shows.

## Rust workspace (`crates/`)

| Crate | Replaces (TS) | Notes |
|---|---|---|
| `ratchet-core` | `packages/core` | config (`ratchet.yaml`, serde + schemars), stats and auto-calibration, verdicts, protected paths, value model, templates |
| `ratchet-ledger` | `core/ledger` (drizzle) | sqlx SQLite, append-only `ratchet_moves` / `spend_events`, `engine_kv` |
| `ratchet-sandbox` | `packages/aws`, sandbox parts of `engine` | aws-sdk-rust, tofu as subprocess, image lookup by tag, reaper, cost |
| `ratchet-env` | `packages/core/src/environment`, `packages/engine/src/environment` | environment drafts (scope none / single / full), validator, cost estimate, brief, drafters (real + mock), approve and lock; depends on `ratchet-core` only |
| `ratchet-bench` | `packages/bench` | evaluator pipeline, dependency snapshots, container images, the bench-host agent binary and the setuid launcher (replaces the C launcher) |
| `ratchet-agents` | `packages/agents` | Claude Code / Codex adapters (spawn the CLIs), runner loop, worktrees, harness detection |
| `ratchet-github` | `packages/github` | octocrab: device-flow sign-in, repos, branches, PRs, commit files |
| `ratchet-engine` | `packages/engine`, `packages/runtime` | the ratchet loop on tokio, sandbox lifecycle, runtimes (simulation / live / hybrid) |
| `ratchet-connectors` | desktop main `connectors*.ts`, secret half of `settings.ts` | saved GitHub / AWS / agent connectors (one default per kind), per-repo selection, migration of the single-account settings, the `SecretStore`s (Keychain). Its `model` module is the wire types of the connectors group |
| `ratchetd` | Electron main process | axum on a unix socket, OpenAPI (`utoipa`), SSE events, LaunchAgent entry |
| `ratchet` | `packages/cli` | clap, API client |

Libraries: tokio, axum, sqlx, serde, schemars, utoipa, aws-sdk-rust, octocrab, clap, tracing,
proptest (stats and the ratchet rule), insta (snapshot tests of reports and API payloads).

## Mac app (`apps/mac/Ratchet`)

Scaffolded with the `new-mac-app` skill (Swift package, `build.sh`, snapshot mode, no Xcode GUI), then:

- **Data**: the generated OpenAPI client plus an `@Observable` store fed by SSE. No SwiftData; the
  ledger lives in `ratchetd`. The client (`Sources/RatchetAPI`) is generated by swift-openapi-generator
  from `api/openapi.yaml` and committed (`tools/generate-api.sh`); it runs over a small POSIX unix-socket
  transport (`UnixSocketTransport`), the same code on macOS and Linux, so the unit tests and a real
  `ratchetd` exercise it without a Mac. There is no sample-data fallback: the sample client (`MockRatchetClient`)
  is for snapshot and test mode only; "Demo mode" is the daemon's own simulation.
- **Design**: Midnight Brass as a custom design kit (`design-kit` skill): tokens from `design/v02.html`
  (one brass accent, hairlines, serif numbers), checked with `layout-grid` and snapshot mode in light
  and dark. Swift Charts for the value staircase and run charts.
- **Screens** (from `design/v02.html` and the current app): Overview, Optimizations, Optimization detail
  (live agents, result and receipt), New optimization (Goal & repo → Connections → Environment →
  Budget), Benchmarks and Templates, Connectors (in the window and in Settings).
- **Mac-native extras** (`os-integrations` skill): menu bar item with running runs, sandbox status and
  "needs you" count; notifications (`UNUserNotificationCenter`, permission asked after the first optimization,
  one switch per category) for wins to merge, environments drafted, budget limits, finished or failed runs and
  expired connectors, a click opens the screen;
  Dock badge; Spotlight for optimizations; Quick Look for reports; keyboard-first navigation.

## Verification

| Layer | How | Where it runs |
|---|---|---|
| Rust | unit, proptest, insta, contract tests on the OpenAPI payloads, ledger migration tests | Linux (this environment) and macOS CI |
| Parity | today's TS test suites ported case by case; demo repos (`examples/`) run end to end in simulation and must produce the same verdicts | Linux |
| Infra | `tofu fmt`, `validate`, `tofu test` unchanged | Linux |
| Mac app | `build.sh` (bundles the daemon), unit tests, a daemon smoke step (`tools/smoke-daemon.sh`: the bundled `ratchetd --mode sim` plus the app's `--selftest-live`), snapshot mode (every page, light and dark) compared with `design/v02/*.png`, grid lint, XCUITest flows replacing `packages/e2e` | macOS CI (GitHub Actions) or the user's Mac attached to the session |

A UI change is done only after its snapshots were looked at (`build-and-verify` skill).

## Big-bang plan

1. **Contract first**: the API types in Rust (`ratchetd` routes, OpenAPI, SSE event enum) mirroring
   today's `RatchetApi` plus Connectors, Overview and environment drafts. Generate the Swift client.
2. **Rust port in parallel workstreams** (one agent each, merged into a single branch): core + ledger;
   sandbox + env; bench + launcher; agents + github; engine + connectors; `ratchetd` + CLI. Each ports
   its TS tests first, then the code.
3. **Mac app in parallel** against a mock `ratchetd` (simulation runtime), screen by screen from the v02
   designs.
4. **Cut-over**: demos pass end to end against the real `ratchetd`; delete `packages/desktop`,
   `packages/e2e` (Electron), and the ported TS packages; update `README.md` and CI.

## Risks and open questions

- **No macOS in this cloud environment**: Swift builds and snapshots need macOS CI or the user's Mac
  (Remote Control). Set up CI before the first screen.
- **aws-sdk-rust and octocrab coverage**: check the few calls we use (SSM, Cost Explorer, Pricing,
  device flow) early.
- **Signing and notarization**: the app and `ratchetd` share a Developer ID team; the LaunchAgent
  needs the signed helper path.
- **Later**: cloud `ratchetd` (Postgres via sqlx, GitHub sign-in, a local runner that connects out so a
  cloud server can still use the user's Claude Code login).
