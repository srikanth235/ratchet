# Design check: app vs `design/*.dc.html`

Generated by `packages/e2e/design-render/report.mjs` from `artifacts/design-check/before.json` and `after.json`.

How it is measured: each `design/*.dc.html` is rendered standalone (`design-render/dc-shim.js`: evaluates `class Component extends DCLogic { renderVals() }`, expands `<sc-for>` / `<sc-if>` / `{{holes}}`, hoists `<helmet>`) at 1440 px and screenshotted to `artifacts/design/<screen>.png`. The desktop app is launched with `RATCHET_ENGINE=dev` (seeded data comparable to the designs) and screenshotted to `artifacts/app/<screen>.png`. `design-render/check.mjs` then reads **computed styles** of corresponding elements in both (declared in `design-render/specs.mjs`) and compares them (colours within 2/255, sizes within 0.5 px, font family by first family actually used).

Re-run: `pnpm --filter @ratchet/desktop build && cd packages/e2e && node design-render/render.mjs && xvfb-run -a node scripts/shoot-app.mjs && xvfb-run -a node design-render/check.mjs after && xvfb-run -a node design-render/fonts.mjs && node design-render/report.mjs` (copy the old `after.json` to `prev.json` first to keep the previous round's column).

"Before" is the app as it was when the design work started; "Previous round" is the build before this round (range switch, KPI chips, metric switch, spans, winning change, evaluator cards, guardrail ticks); "After" is the current build. For the dev engine the design tools slow the simulated agents to one turn an hour (`RATCHET_DEV_TICK_MS`) so the seeded ledger holds still while screens are measured.

## Where the new elements get their data

Every number is read from the ledger or the engine; nothing is filled in by the renderer.

| Element | Source |
|---|---|
| Range switch 7d / 30d / 90d + KPI cards | `listOptimizations({ range })` → `main/kpis.ts`: ratchet moves, baselines and spend events inside the window |
